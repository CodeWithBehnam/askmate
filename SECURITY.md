# Security Policy

## Supported Versions

Security fixes are handled on the latest released version of AskMate.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Older releases | Best effort |

## Reporting a Vulnerability

Please do not report security vulnerabilities in public GitHub issues.

Report security concerns privately through GitHub's private vulnerability reporting if it is enabled for this repository. If it is not enabled, contact the repository owner from the GitHub profile and include enough detail to reproduce the issue.

Useful details include:

- Affected AskMate version or commit.
- Obsidian version and operating system.
- Steps to reproduce.
- Impact and any known workaround.
- Whether API keys, note content, generated files, or provider requests are involved.

## Scope

Security-sensitive areas include:

- Provider API key and MCP secret storage and retrieval.
- Request privacy controls and context capture.
- Apply and partial Apply write safety, including default append behaviour and explicit full-note replacement gates.
- File path handling for generated notes and images.
- Import/export of workflow presets.
- Rendering of model replies in the sidebar.
- Prompt construction around untrusted note, attachment and evidence content.
- Provider base URL validation, including the fixed vendor addresses.
- MCP servers: trust records, the per-call approval gate, tool fingerprints, how local servers are launched, and how tool descriptions and results reach the model.
- Skills: review and trust of vault skills, and how skill text enters a prompt.
- Mermaid diagrams generated by a model, and the guard that stops them loading remote resources.
- Note history, saved conversations, review queue, skill and MCP settings and usage data stored in the plugin's `data.json`.
- Any behaviour that could expose private note content unexpectedly.

## Current Safeguards

These are the protections a report would bypass. They reduce risk; they are not guarantees.

- Model replies are untrusted. Before rendering a reply in the sidebar, and again before it is written to a note, AskMate turns remote Markdown images into links that are not loaded, shows HTML tags that would load network resources (such as `img`, `iframe`, `video`, `link` and `style`) as text, relabels fenced code blocks whose language other plugins could execute (such as `dataviewjs`) so those processors do not run, and blocks links to schemes such as `obsidian://`, `file:` and `javascript:`. Context image previews load only vault files and `data:image/` URIs.

- Mermaid diagrams from a model pass an allowlist. AskMate builds the header and styling itself, and rejects directives, `click` handlers, URLs, HTML and custom CSS in model output.
- Note content is treated as untrusted data in prompts. Notes, attachments, evidence excerpts, history, skills and tool results are wrapped in delimiter tags, AskMate's own delimiter tags are escaped inside that content, and the prompt tells the model not to follow instructions found there. This is prompt-injection hardening, not a guarantee: a model may still be influenced by what it reads.
- Provider base URLs must use `https://` for remote hosts. Plain `http://` is accepted only for addresses on the same machine or network. OpenAI, Anthropic, Google Gemini and OpenRouter always use the vendor's own address, so a settings file cannot redirect a key to another host.
- AskMate refuses to use an incomplete or filtered reply to replace note text, and asks for confirmation before a replacement when the note or selection was truncated by the context budget.
- API keys and MCP secrets are read through Obsidian `SecretStorage`; settings store only secret names, and provider error messages redact keys.
- MCP is off by default. A server needs trust on each device before it starts or is contacted, and any change to its definition needs trust again. Trust is stored outside `data.json`, so a synced definition arrives untrusted. Every tool call asks for approval and shows the full arguments. Each tool definition is fingerprinted, and a changed tool needs fresh approval.
- Local MCP servers start with an argument list and no shell, with a minimal environment, only on desktop, and `child_process` is imported in one file, `src/mcp/launch.ts`. They run with the user's permissions, and Obsidian cannot sandbox them.
- Tool descriptions and results are cleaned of control, zero-width and bidirectional characters, capped, kept out of the instructions and rendered through the sanitiser. Tools never write to the vault.
- Vault skills are inert until the user reviews their text and approves its SHA-256 hash. A skill is instruction text only and cannot call tools or write files.

## Response Expectations

The maintainer will triage reports as time permits. Valid reports should receive an initial response as soon as practical, with follow-up questions if more detail is needed.

Please give the maintainer reasonable time to investigate before public disclosure.
